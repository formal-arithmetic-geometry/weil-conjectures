# PerfIssues DefEq Cost Anatomy

Lean 4.35.0, source snapshot 1ef1fddac73. Seven assigned cases were measured on the release kernel and with the observational counters-only kernel; detailed traces were collected on the same stored-expression or in-situ roots, with aligned controls also run in both modes. All instrumented timings below are measured, not inferred. The validated kernel's own overhead check reported a fast probe at 1.37 s release, 1.60 s counters, 1.61 s trace, and a slow NativePullTensor probe at 79.33 s source, 80.66 s counters, 86.30 s trace. Instrumentation changes wall time and memory substantially on some probes, so release timings remain the performance reference; source probes of different scope cannot be used for per-case overhead ratios.

The root/reduction/comparison columns are counters-only measurements. Fan-out maxima are over each full trace probe, not necessarily the selected root. Distinct pairs and repeated-pair time shares are from the corresponding trace root; the share divides repeated-pair exclusive comparison time by that trace root's total exclusive comparison time. Pair capture is capped at five million calls for the largest roots. Root ID 32641 for PR2122 is the largest reported root across the original module; a declaration/recursor-branch mapping is not recorded.

These selected roots account for 415.726 s instrumented wall time: 219.384 s (52.8%) exclusive comparison and 196.343 s (47.2%) exclusive reduction (the displayed components differ by 1 ms from the displayed root total because of rounding). The totals cover one representative root per case, not all module work. Seven of seven cases are outcome F (mixed). None is unambiguously reduction-dominated or comparison-dominated: NativePullTensor and PR1625 lean toward comparison, and PR2122's selected root leans toward reduction. PR1556 (depth 213) and PR1625 (125) are deepest; PR1625 (fan-out 44), PR2122 (31) and NativePullTensor (28) are widest among these probes. PR1563 and PR2122 distribute cost across multiple roots. NativePullTensor and PR1625 concentrate release cost at accessor/application sites, while PR1627's generated fields have different costs. PR1624 has two expensive dependent endpoints.

Dependent domains and proposition types are implicated by release argument probes in all seven cases, but the patch's proposition timer is nested under recursive comparisons and can exceed root wall time. Thus outcome C or proof-type dominance cannot be established quantitatively. The bounded pair trace does not record local-context identity. Repeated exact pairs are common, yet measured repeat-exclusive time is only 0.5-11.2% of trace comparison time, so outcome D is unsupported for these selected roots. Peak RSS rises substantially in instrumented runs; Expr allocation and GC attribution were unavailable, so outcome E is not established. The top-20 child lists, depth/fan-out histograms, branch counters, and proposition groups are preserved in the per-case trace artifacts. Historical reference-case instrumented data belongs to the separate historical batch and is not available in this dataset worktree; no cross-batch signature match is claimed here.

Release controls show that aligning the expensive premise removes or sharply lowers the local conversion in NativePullTensor, PR1556, and PR1625. The source-level aligned controls are also faster for PR1627, PR1563, PR1624, and PR2122, but those controls change larger construction or module boundaries. No root-time total is inferred by adding inclusive parent and child measurements.
