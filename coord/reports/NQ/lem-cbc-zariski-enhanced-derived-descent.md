## What was wrong in the earlier sandbox

The previous basis-hypercover node was false. For example take B = Spec(R), basis {B}, and the etale cover Spec(C) -> Spec(R). A refinement of its degree-zero cover by copies of the base open would require an R-morphism Spec(R) -> Spec(C), equivalently an R-algebra homomorphism C -> R; none exists. Pulling back a base-open cover of an etale object produces etale objects over those opens, not copies of the base opens. Tag 0DAX, `hypercovering.tex`, label `lemma-hypercovering-site`, assumes every object has a cover by members of the proposed subcategory; this assumption failed.

## Source error: a comma object need not be final

In the ordinary prototype Tag 03A0, `sites.tex`, proof of `lemma-equivalence`, the sentence calling (U, id) final in the category of pairs (U', u(U') -> u(U)) is too strong when u is only locally full. For a small example, take C to be the poset 0 < 1 with its singleton cover 0 -> 1 and otherwise trivial covers, D the one-object trivially topologized category, and u the constant functor. It is cover-preserving, cover-lifting, locally full, locally faithful and cover-dense. For U = 0, the comma category is C and (0, id) is not final, since there is no arrow 1 -> 0. Evaluation of a limit at (U, id) is still a defined map, and the ensuing local-fullness/local-faithfulness sheaf argument proves the asserted equivalence without finality. The new dense-hypersheaf comparison states an actual homotopy right Kan extension and a comparison theorem, not a reduction of that homotopy limit to an alleged final object. In the total category, the singleton i -> k is declared covering. Pulling back its covering sieve along j -> k gives the empty sieve, so the topology forces the value at j to be zero, and the other singleton covers force all values to be zero.
