# D2 maintenance: WeilConjectures.PoincareDuality.Verdier

The six repeated failures were caused by an upstream data defect combined with a stage-3 tool contract.
`lean/WeilConjectures/PoincareDuality/Verdier.lean` contained the unused theorem
`AlgebraicGeometry.ProEtale.CondensedRing.isIso_verdierBiduality` with its sole `sorry`.
The unrestricted relative biduality claim is false for singular bases (the nodal curve
`Spec(k[x,y]/(xy))` at its origin gives a counterexample). The actual Poincare consumer
uses only `isIso_verdierExchange`; it does not use the false theorem or the absolute-exchange
tail. Every worker that removed the theorem was rejected by `tools/stage3_gate.py`, which
forbids removing declarations from the adopted `WeilConjectures.*` source tree; workers that
left it open were rejected because `deliver3.py` requires the sole hole to be closed.

## Repair

The source module was repaired by removing the false theorem and its unused absolute-exchange
definitions/import dependency, retaining `verdierBiduality` only as a definition with an explicit
`STATEMENT-DISPUTED` note. The corresponding live source repair is in build commit
`1380e3de97` (`build 2026-10-17T05:26:43Z`); the current `sheaf-dag` tree contains the repaired
module. The source and sorry-ledger snapshots were preserved as
`lean/WeilConjectures/PoincareDuality/Verdier.lean.bak-maint-D2-verdier-1792214289` and
`coord/sorry-ledger.tsv.bak-maint-D2-verdier-1792214289`.
