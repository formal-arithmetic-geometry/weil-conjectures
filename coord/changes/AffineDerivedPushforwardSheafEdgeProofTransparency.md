# AffineDerivedPushforwardSheafEdge proof-local transparency

## Reason

The stage-3 preflight classifies any new attribute command as an interface change,
including a local attribute. It therefore requests this record. The directive
keeps the concrete direct-image implementation closed during homology comparison
simplification. It is unfolded explicitly in the finite-limit and ordinary-derived
comparisons. No definition, theorem signature, visibility, or global attribute is
changed. There are no forced adaptations. This is a proof-local elaboration change,
not a change to the direct-image object or the meaning of any target.

## Old

There was no local transparency directive. The exposed definition in
RingedSpaceDerivedDirectImage was and remains:

```lean
def moduleDirectImage {X Y : RingedSpace.{u}} (g : X ⟶ Y) :
    SheafOfModules.{u} (moduleRings X) ⥤ SheafOfModules.{u} (moduleRings Y) :=
  SheafOfModules.pushforward (F := Opens.map g.hom.base)
    (R := moduleRings X) (S := moduleRings Y)
    ⟨Functor.whiskerRight g.hom.c (forget₂ CommRingCat RingCat)⟩
```

## New

The definition above is identical. The assigned module alone adds this directive
before its theorem:

```lean
attribute [local irreducible] RingedSpace.moduleDirectImage
```

The attribute has local scope and is not exported to importers. Explicit unfolding
in the proof gives exactly the original definition where it is needed. The full
signature of exists_affineDerivedPushforwardSheafEdge is unchanged verbatim.
No Challenge statement or definition it uses changes, so no target-statement
review is reopened.
